M3 plan / base coverage

M3 (base R, clean room) has started: the plan, the coverage metric (26.4 % of base's 1 362 exports agree with R 4.6.2 at v0.11.0), and how it is measured.

You are reading the documentation of an outdated version, whose text may no longer be accurate. Go to the latest version.

M3 has started. M2 gave an evaluator with 175 of R’s 210 primitives; M3 is the rest of what library(base) exports (1 152 closures). The first slice of M3 is in v0.7.0 (pull request 12); slice 5, which starts the base library, is v0.8.0, slice 6 (strings and format) is v0.9.0 and v0.9.1, slice 7 (conditions and the call stack) is v0.10.0, slice 8 (environments and namespaces) is v0.11.0, the current release. The plan is docs/m3-plan.md.

How it is measured

  • testdata/base/exports.tsv: the 1 362 functions exported by base, with their kind (primitive or closure), generated by the oracle (R 4.6.2) and regenerated when R is bumped.
  • testdata/base/needs.tsv: for each closure, the names of the .Internal functions it calls; internals.tsv: per internal, the number of call sites and of closures. They hold names and counts only, obtained from the running oracle; nothing of base’s source is kept.
  • Coverage is the fraction of base exports that the evaluator implements and for which a passing golden exercises the function (a name that appears as a call in testdata/eval, whose snippets all agree with R). It is printed by go run ./cmd/rparity basecov and recorded in the README at each tag.
  • A function counted once is not uncounted when more cases are added. A refusal (eval.Unsupported) counts as not implemented.
  • The metric is deliberately a floor: one passing snippet per function is the entry ticket; the differential fuzz modes and the base R test suite (run through the oracle’s own snippet generator, never copied) are what make a function trustworthy.

basecov also prints, from needs.tsv, the greedy order of the missing internals that completes the most closures, and the count of closures that need none (a rewrite suffices): 701 of the 1 042 closures not yet implemented at the time the plan was written. Base’s calls to .Internal are spread flat, so their frequency ranks nothing.

The clean-room rule for base functions

  • Specification: R’s documentation and the observed behaviour of the oracle.
  • Never read, never copied: the files of src/library/base/R, src/main, src/nmath, tests/.
  • A function is written from its help page and from experiments: snippets in testdata/eval/*.R, turned into goldens by the oracle, and the code is made to agree.
  • Two homes for the code: Go natives (eval/*.go) for hot paths and loops over vectors, and our own R (eval/baselib/*.R, embedded) for glue closures.
  • .Internal itself is not provided (it is refused): base closures are rewritten and do not go through it. The 401 internals base calls are a measure of work, not an API to reproduce.

A slice is tagged when its goldens, fuzz, FuzzEval and bomb tests are green and basecov has moved. Slices 5 onwards are planned, not started.

Gates, per slice

  1. goldens from our own snippets, compared with the oracle byte for byte (value, visibility, output, stderr, warnings, error message and call);
  2. a differential fuzz mode for the new area, with every exclusion counted;
  3. FuzzEval for the whole evaluator, each crasher kept in the corpus;
  4. bomb tests that assert a refusal under GOMEMLIMIT, and the safe defaults of eval.Options;
  5. performance against the reference, single core, once a function is on a hot path.

Collation (decided in slice 4)

R 4.6.2 started with LC_ALL=C.UTF-8 (the oracle’s locale) still orders strings with ICU, not by code point: sort(c("b", "A", "a", "B")) is "a" "A" "b" "B", punctuation sorts before digits before letters, and accents come after the plain letter. The evaluator reproduces this for Latin text (eval/collate.go: three-level comparison, ICU’s order of the ASCII punctuation), for sort, order, ls, < and > on strings, and min/max of strings; == is exact. Strings outside Latin script compare by code point after the Latin letters (a documented divergence). method = "radix" and LC_COLLATE=C will select code-point order when Sys.setlocale exists (slice 6).
