Evaluator

M2, package eval: the design choices, slices 1 to 4 (175 of 210 primitives and 110 base closures, 1 570 of 1 570 goldens at v0.11.0), judged by the oracle; M2 is complete, and M3 has added a base library, strings, conditions, environments and namespaces.

You are reading the documentation of an outdated version, whose text may no longer be accurate. Go to the latest version.

Status: M2 is complete (slices 1 to 4), in v0.7.0 (pull request 12, 2026-11-07): 175 of R’s 210 primitives and 110 base closures, 1 154 of 1 154 goldens at that release. The other 35 primitives are refused with an error that says why (eval.Unsupported, listed by go run ./cmd/rparity missing, not counted as implemented): the complex and raw types, S4, formulas and expression vectors, foreign calls (.C, .Call, .External*, .Fortran, lazyLoadDBfetch), .Internal, and the tracing and debugging primitives. M3, base R, has started: see M3 plan / base coverage.

Later releases, all 2026-11-07: v0.7.1 (pull request 13) takes tre v0.1.1 and streams the sub/gsub loop (BenchmarkGsubGroup, 20 000 lines: 247k to 87k allocations per operation, 9.0 to 4.6 MB per operation; the timing against R is deferred because of machine load, so no speed is claimed). v0.8.0 (slice 5) starts the base library: our own R in eval/baselib/*.R (BSD, clean room) plus Go natives, 1 202 of 1 202 goldens, vector fuzz 18 000 of 18 000, base coverage 22.2 %. v0.8.1 (pull request 16) takes tre v0.1.3. v0.8.2 (pull request 18) makes arithmetic, comparison and &/| on two arrays with different dims raise R’s non-conformable arrays, and an array against a longer vector raise dims [product n] do not match the length of object [m] (zero-length arrays are fine, as in R); it also keeps dimnames padding in step (both were FuzzEval crashers). v0.9.0 and v0.9.1 (slice 6) add the string and format functions. v0.10.0 (slice 7) adds restarts and the call stack, 1 302 of 1 302 goldens, base coverage 24.4 % (23.3 % at v0.9.0). v0.11.0 (pull request 27, 2026-11-08, slice 8) adds environments and a one-namespace model: 1 570 of 1 570 goldens, env fuzz 15 000 of 15 000, base coverage 26.4 % (360 of 1 362). Slices 6 to 8 are described below.

History: slice 2 was released in v0.3.0 (pull request 8); v0.4.0 (pull request 9) bounded the session limits by default; v0.5.0 (pull request 10, 2026-11-05) added slice 3; v0.6.0 (pull request 11, 2026-11-06) made its regular expressions a port of TRE (v0.5.0’s were an approximation on Go’s regexp); see Regular expressions. The design is docs/m2-design.md; the API is on Eval API.

Design choices

  • Clean room. R’s C code is a specification, never a source. The design is written from the R Language Definition, R Internals, the help pages and what the oracle (GNU R 4.6.2) does; each slice is checked by the oracle lane before it is merged.
  • Bounded. Recursion depth (R’s own expressions limit, 5000), vector allocation size and evaluation steps are session limits, refused with R’s own error, never a Go crash.
  • Typed Go slices for vectors, not []interface{}: arithmetic loops run over []float64 and []int32, and NA is a value inside the slice (R’s INT_MIN and NaN-payload conventions), never a side bitmap.
  • Calls are *Lang with an argument slice, not pairlists; a real pairlist type is only for formals, attributes and pairlist().
  • Attributes are an ordered slice, because their order is observable.
  • Symbols are interned, so quote(x) == quote(x) is pointer equality.
  • *Missing is its own type, for f(x, ) and missing().
  • No byte-code: the AST walker is the semantics; a faster tier would be a later, measured decision.
  • Closures take promises: lazy arguments, missing, ..., with R’s three-pass argument matching (exact name, unique partial name, position).
  • Lexical control flow is not panic-based on the hot path (break, next, return travel as a flow code); errors and non-lexical exits use a typed Go panic recovered at the owning context.
  • Conditions: handlers are a stack on the session. Exiting handlers unwind with a typed panic caught by their tryCatch, calling handlers run with the stack truncated below them, and restarts are found by name. Errors are signalled as conditions before they end the evaluation, so tryCatch(error=) and withCallingHandlers(error=) see them.
  • Replacement functions use always-copy semantics; the ownership optimisation stays deferred.
  • The oracle judges. Goldens are R’s answers to inputs written in the repository, compared byte for byte; the tests replay them without R.

Coverage: 102 of R’s 210 primitives and 94 base closures

Slice 1: constants and symbols, environments, <-/=/<<-, function and closures with R’s three-pass argument matching, promises (lazy arguments, missing, ...), {, if, for, while, repeat, break, next, return, quote, and arithmetic, comparison and logic with R’s recycling, NA rules, type promotion and integer overflow; c, list, length, is.*, as.*, sum/prod/min/max/any/all, abs/sqrt/floor/ceiling/exp, seq_len, seq_along.

Slice 2:

  • replacement functions with copy-on-modify (x[i] <- v, x[[i]] <- v, x$a <- v, names(x) <- v, attr(x, "a") <- v, f(g(x)) <- v, user "f<-" functions);
  • [, [[ and $ with R’s drop, NA, out-of-bounds, negative, partial-matching and matrix/array rules;
  • attributes (attr, attributes, class, dim, dimnames, levels, structure; factors keep levels);
  • S3 (UseMethod, NextMethod, internal dispatch on [, [[, $, their assignment forms, length, print, and the group generics Ops, Math, Summary);
  • the condition system (stop, warning, message, signalCondition, tryCatch with finally, withCallingHandlers, try, on.exit, the restarts muffleWarning and muffleMessage, suppressWarnings, suppressMessages, custom conditions);
  • print and auto-print that reproduce R’s text for atomic vectors, named vectors, lists, matrices and arrays, factors, conditions, closures and attributes (R’s formatReal with 7 digits, [k] labels at width 80).

Slice 3:

  • environments as values (environment, environment<-, new.env, globalenv, emptyenv, baseenv, parent.env, parent.frame, sys.call, sys.function, assign, get, get0, exists, mget, ls, rm, local, eval, evalq, list2env, as.environment);
  • the apply family (lapply, sapply, vapply, Map, mapply, Reduce, Filter, Find, Position, do.call, match.fun);
  • character functions (nchar, substr, substring, strsplit, sprintf, format, toupper, tolower, casefold, chartr, trimws, startsWith, endsWith, Encoding, enc2utf8, utf8ToInt, intToUtf8, validUTF8);
  • regular expressions (grepl, grep, sub, gsub, regexpr, gregexpr, regmatches): POSIX extended syntax with leftmost-longest matching, on a Go port of TRE since v0.6.0 (see Regular expressions).

Slice 4 (v0.7.0) completes M2: the rest of the math group (log family, trigonometric and hyperbolic functions, gamma family, trunc, sign, round and signif with R 4’s rounding algorithm), cumsum/cumprod/cummax/cummin, range, is.finite/is.infinite/is.nan, anyNA, nzchar, switch, substitute, nargs, ...length/...elt/...names, call, as.call, forceAndCall, ::/::: (resolved in the base and global environments), %*%/crossprod/tcrossprod, seq.int, proc.time, and typeof, mode, deparse, as.name, unique, duplicated, match, %in%, factor, levels, format of factors. Collation is decided and documented: see M3 plan / base coverage.

Slice 8 (M3, v0.11.0) adds environments and a one-namespace model. Bindings: lockBinding, unlockBinding, bindingIsLocked, lockEnvironment(bindings =), environmentIsLocked, makeActiveBinding, bindingIsActive, activeBindingFunction, delayedAssign; every assignment (<-, <<-, assign, $<-, [[<-, list2env, replacement forms) honours locks and runs active bindings, with R’s messages and calls; the base environment and all its bindings are locked as in R (assign("sum", 1, baseenv()) is refused). rm takes inherits; get/get0/exists/mget take mode, inherits and ifnotfound and give R’s messages; exists does not force a promise. as.list is generic (as.list.environment with all.names and sorted, .default, .function, .factor); eapply, with, within (lists), withVisible, names(env). Environments carry attributes, so S3 dispatch works on them. Namespaces: asNamespace, getNamespace, isNamespace, isBaseNamespace, getNamespaceName, getNamespaceExports, isNamespaceLoaded, requireNamespace, .BaseNamespaceEnv, .GlobalEnv, topenv, :: and :::. The namespace of base is an environment of its own (printed <environment: namespace:base>, enclosed by the global environment) that shares the base frame. Errors raised directly under eval, evalq, local and with report R’s call. An active binding that read itself used to overflow the Go stack; it is fixed, with a corpus entry and a bomb test.

Slice 7 (M3, v0.10.0) adds restarts (withRestarts with functions and arguments, computeRestarts, findRestart, invokeRestart(r, ...), tryInvokeRestart), the call stack (sys.nframe, sys.calls, sys.frames, sys.frame, sys.on.exit), Recall, match.call (positional, partial and exact matching, ... expanded from the caller, expand.dots), errorCondition, warningCondition, geterrmessage, and $ on a call. A calling handler or finally no longer changes the visibility of the value.

Slice 6 (M3, v0.9.0 and v0.9.1) adds string functions: strrep, substr<-, strtoi, make.unique, basename, dirname, formatC (formats d, f, e, g, s; flags -, 0, +, space; big.mark; negative width), prettyNum, toString, sQuote/dQuote (curly quotes, as the oracle’s UTF-8 locale gives), shQuote, noquote and print(quote = FALSE), file.path; part 2 adds format(big.mark =), formatC(mode =, format = "fg"), shQuote(type = "csh"/"cmd"/"cmd2") and match.arg, and sprintf("%#x", 0) prints no prefix, as C does. Text produced by sprintf, formatC and strrep counts against MaxAlloc.

Slice 5 (M3, v0.8.0) starts the base library. eval/baselib/*.R is base R’s glue written by us, BSD, under the clean-room rule of the M3 plan (isTRUE, isFALSE, xor, Negate, setNames, union, intersect, setdiff, is.element, append, head, tail, ifelse, nrow, ncol, NROW, NCOL, lengths, rep_len, diff, outer), embedded, parsed once and evaluated into the base environment of each session (43 µs per NewSession). Go natives: as.vector, order, rank (average, first, min, max), pmax, pmin, which.max, which.min, tabulate, rowSums/colSums/rowMeans/colMeans, t, diag, mean, stopifnot.

matrix, array, letters and LETTERS are there for the tests. Each primitive and each of the 110 closures (print, cat, paste, tryCatch, structure, inherits, …) is exercised by the goldens; the rest of the 35 primitives that remain are refused with an error that says why. Errors and warnings are R’s own: Error in f(1) : object 'y' not found.

Known divergences

Of slice 2:

  • [[<- with a vector subscript on a list that goes through an NA, an absent name or a logical (x[[c(1, NA)]] <- v, x[[c("a", "c")]] <- v on an unnamed list): R’s message comes from its recursive indexing and ours differs (31 of 26 000 fuzz cases in the earlier run). A few R messages for [[<- on atomic vectors with 0, negative or NA subscripts follow the oracle for the common cases only.
  • Function printing: print of a function does not show R’s <environment: 0x...> address (a placeholder), and .Primitive formals are not shown.
  • Printing an array with more than 2^20 slices or 2^22 rows is refused instead of running for ever. print of list elements dispatches only to the methods R registers itself (factor, condition), as R does.

Of slice 8 (v0.11.0):

  • There is no package loading: no library, require, loadNamespace, attach, search, sys.source (planned with the slices that need them).
  • The installed packages other than base (stats, utils, …) resolve through our base environment (utils::head works, stats::sd is “‘sd’ is not an exported object”), and any other name is there is no package called ‘x’.
  • parent.env(globalenv()) is base; R’s is the last attached package.
  • as.list.environment and names(env) list in creation order, where R’s hashed order is unspecified.
  • sys.call() and parent.frame() inside eval/local do not see R’s eval frame.
  • The text requireNamespace("foo") writes without quiet was read from the oracle, not goldened (its harness adds a connection warning).
  • print of an environment does not list its attributes.
  • getNamespace(<environment>) raises R’s message with another call.
  • within has no data frame method.

Of slice 7 (v0.10.0), all because R runs tryCatch and try through closures we do not have:

  • the conditionCall of a stop() made directly inside try() or tryCatch() at top level is empty here, and R’s internal call there (doTryCatch(...), try(...));
  • match.call(expand.dots = FALSE) keeps ... as a list where R keeps a pairlist (deparse shows list( for pairlist();
  • absolute frame numbers differ from the oracle’s, which runs each snippet inside its own harness frames, so the goldens compare numbers of frames relative to a starting point;
  • computeRestarts has no top-level abort restart.

Of slice 5 (v0.8.0):

  • A matrix whose dimnames carry names (names(dimnames(x)), as table() makes) prints without the variable-name header lines R adds.
  • lgamma, digamma and trigamma are less accurate than R’s: an open defect, issue 14; the fuzz compares them through signif(x, 12) and counts them.
  • mean sums in float64 (with R’s second pass) where R uses long double: last-bit differences are possible on long sums.
  • The math fuzz compares libm functions within 4 ulp (largest seen: 2), not exactly: the last bit of those functions depends on the C library.

Of slice 3:

  • Regular expressions: TRE’s approximate-matching syntax is not ported, non-ASCII classes use Go’s Unicode tables, perl = TRUE is refused, and grepl is 1.44 times slower than R (an open defect); see Regular expressions.
  • sort of non-atomic values is not implemented.
  • Collation (decided in slice 4): strings sort and compare as R 4.6.2 does under the oracle’s C.UTF-8, which is ICU order, not code point (punctuation, digits, letters; accents after the plain letter; lowercase before uppercase). Strings outside Latin script compare by code point after the Latin letters, a documented divergence. See M3 plan / base coverage.
  • Widths of sprintf and format above 2^24 are refused. sprintf("%05d", NA) zero-pads the NA as macOS does, where glibc pads with spaces (the C library decides in R, so the golden leaves it out).

From the platform rather than the semantics:

  • The bits of a NaN (its sign, whether it is quiet) are whatever the hardware made of it, so goldens and the fuzz compare NA against NaN, not their payloads.
  • exp and the power with a fractional or negative exponent can differ from the C library’s pow/exp in the last bit (the fuzz keeps the exponents integral and leaves exp out; they come with go-numerics in M4). The 2 of 190 000 arithmetic fuzz cases are one of each (a pow last bit, and NA %% 3 added to a NaN).
  • min/max of a character vector mixed with numbers is not collated like R’s.
  • The modulus family is written with explicit fused multiply-adds, as R is compiled on arm64, so it gives the same result everywhere; R on x86-64 Linux does not fuse, so its %% of huge doubles can differ there (the CI lane reports the evaluator fuzz on Linux, it does not gate it).

Not started

M3 (base R) is in progress. M4 to M8 (stats, graphics, notebook bridge, wasm playground, CRAN ports) are planned.
