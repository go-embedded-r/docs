## How it is measured

- `testdata/base/exports.tsv`: the 1 362 functions exported by base, with their
  kind (primitive or closure), generated by the oracle (R 4.6.2) and regenerated
  when R is bumped.
- `testdata/base/needs.tsv`: for each closure, the names of the `.Internal`
  functions it calls; `internals.tsv`: per internal, the number of call sites and
  of closures. They hold **names and counts only**, obtained from the running
  oracle; nothing of base's source is kept.
- **Coverage** is the fraction of base exports that the evaluator implements and
  for which a passing golden exercises the function (a name that appears as a
  call in `testdata/eval`, whose snippets all agree with R). It is printed by
  `go run ./cmd/rparity basecov` and recorded in the README at each tag.
- A function counted once is not uncounted when more cases are added. A refusal
  (`eval.Unsupported`) counts as not implemented.
- The metric is deliberately a floor: one passing snippet per function is the
  entry ticket; the differential fuzz modes and the base R test suite (run
  through the oracle's own snippet generator, never copied) are what make a
  function trustworthy.

`basecov` also prints, from `needs.tsv`, the greedy order of the missing
internals that completes the most closures, and the count of closures that need
none (a rewrite suffices): 701 of the 1 042 closures not yet implemented at the
time the plan was written. Base's calls to `.Internal` are spread flat, so their
frequency ranks nothing.

## The clean-room rule for base functions

Since v0.12.2 the rule is enforced by a similarity gate, an oracle guard and a
provenance record: see [Clean room]({{< relref "clean-room" >}}).

- **Specification**: R's documentation and the observed behaviour of the oracle.
- **Never read, never copied**: the files of `src/library/base/R`, `src/main`,
  `src/nmath`, `tests/`.
- A function is written from its help page and from experiments: snippets in
  `testdata/eval/*.R`, turned into goldens by the oracle, and the code is made to
  agree.
- Two homes for the code: Go natives (`eval/*.go`) for hot paths and loops over
  vectors, and our own R (`eval/baselib/*.R`, embedded) for glue closures.
- **A first draft that fails the gate becomes a Go native**, written from the
  Rd page and the oracle, never reshaped in R; the failed first-draft score is
  recorded in the pull request (v0.14.1, see [Clean room]({{< relref "clean-room" >}})).
- `.Internal` itself is not provided (it is refused): base closures are rewritten
  and do not go through it. The 401 internals base calls are a measure of work,
  not an API to reproduce.

### Shared engines (decided 2026-11-10 and 2026-11-11)

go-embedded-r does not write its own copy of an engine that several languages
of the fleet need ([go-embedded-ruby/ruby#918](https://github.com/go-embedded-ruby/ruby/issues/918)).
It binds the shared library and keeps only a thin layer that is faithful to GNU
R: call shapes, argument defaults, the result lists, the messages.

- **Numerics** (M4, stats): `optim`, `optimize`, `uniroot`, `nlm`, `nlminb`,
  `nls`, `integrate`, ODE solvers, and the special functions (`gamma`, `beta`,
  `besselJ` and the rest) bind
  [go-numerics](https://github.com/go-numerics). Where GNU R's algorithm differs
  from go-numerics' default, the R layer selects R's (for example `optim`'s
  Nelder–Mead constants, `uniroot`'s tolerance rule, `integrate`'s QUADPACK
  routine) and records in its divergences when a result is not bit-identical to
  GNU R's. go-numerics now states an accuracy contract: a bound on the error
  against an extended-precision oracle (math/big or mpmath), see go-numerics
  optimize#61 and special#69. When a result is not bit-identical to GNU R's,
  the R layer quotes that bound as the guarantee instead of calling the
  difference "last-bit noise"; bit-exact arithmetic stays an option.
- **Statistics** (descriptive statistics, tests, the distributions): bind
  [go-statistics/stats](https://github.com/go-statistics/stats) (v0.1.1 since
  slice 19), and later [go-statistics/models](https://github.com/go-statistics/models)
  for `lm`, `glm` and `anova`; not go-numerics, which has no statistics kernel.
  The R layer keeps the glue (NA, `na.rm`, `use=`, `names`, recycling) and
  binds a function only where go-statistics meets the bound this repository
  states against math/big (the test is in `eval/stats18_bind_test.go`); where
  it does not, the kernel stays here and the gap is listed in the README, for
  the owner of go-statistics to close. The upstream gaps are
  [go-statistics/stats#24](https://github.com/go-statistics/stats/issues/24),
  [#25](https://github.com/go-statistics/stats/issues/25),
  [#26](https://github.com/go-statistics/stats/issues/26) and
  [#27](https://github.com/go-statistics/stats/issues/27).
- **What R does better goes upstream.** When R's reference has an algorithm, a
  default or a test problem that go-numerics lacks, it is added to go-numerics
  for the whole fleet, not to the R layer. This applies only to what is
  available outside R's own GPL text: published papers and netlib's public
  domain or BSD code (QUADPACK, MINPACK, PORT). R's own C and R sources, nmath
  included, stay unread here and are never ported into a shared library.
- **Linear algebra**: slice 13, done in slice 20 (v0.22.0) on
  [go-ndarray](https://github.com/go-ndarray/ndarray) v0.44.0's `linalg`. What it
  lacks (LU factors, a condition estimator, a pivoted QR, `dqrdc2`, `dormqr`,
  `dtrtrs`, a pivoted Cholesky) is written here and listed in the README as gaps
  for its owner.
- **Regex `perl = TRUE`**: go-regexp/pcre2. **Compression** (`gzfile`,
  `memCompress`): the shared zlib. **Random numbers** (M4): the shared bit
  generators, as long as their state reads back as R's `.Random.seed`.
- **Files, environment, clock**: go-embedded-r has the no-host mode (the
  default in-memory tree) and the confined-root mode (`Options.FileRoot`) since
  v0.13.0. It adopts the shared host and sandbox layer
  ([go-embedded-julia/julia#32](https://github.com/go-embedded-julia/julia/issues/32))
  when that layer has both modes.

## Gates, per slice

1. goldens from our own snippets, compared with the oracle byte for byte (value,
   visibility, output, stderr, warnings, error message and call);
2. a differential fuzz mode for the new area, with every exclusion counted;
3. `FuzzEval` for the whole evaluator, each crasher kept in the corpus;
4. bomb tests that assert a refusal under `GOMEMLIMIT`, and the safe defaults of
   `eval.Options`;
5. performance against the reference, single core, once a function is on a hot
   path.

## Collation (decided in slice 4)

R 4.6.2 started with `LC_ALL=C.UTF-8` (the oracle's locale) still orders strings
with ICU, not by code point: `sort(c("b", "A", "a", "B"))` is `"a" "A" "b" "B"`,
punctuation sorts before digits before letters, and accents come after the plain
letter. The evaluator reproduces this for Latin text (`eval/collate.go`:
three-level comparison, ICU's order of the ASCII punctuation), for `sort`,
`order`, `ls`, `<` and `>` on strings, and `min`/`max` of strings; `==` is exact.
Strings outside Latin script compare by code point after the Latin letters (a
documented divergence). `method = "radix"` and `LC_COLLATE=C` will select
code-point order when `Sys.setlocale` exists (slice 6).
